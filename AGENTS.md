## What this project is

A **Buy-vs-Rent mortgage calculator for the German market**. Pure TypeScript
single-page app: Vite + React + Plotly, fully client-side (no backend, no
cookies, only `localStorage`). Published on **GitHub Pages** via
`.github/workflows/deploy.yml`. Generated with AI (Mistral Vibe) — state this
prominently in any user-facing docs; it must not be removed from the README.

## Repository layout

```
src/engine/    pure calculation domain (mortgage, invest, monte-carlo,
               sensitivity, simulate, params registry, state-io)  — no DOM
src/mc-worker.ts   Web Worker entry for Monte-Carlo runs (sync fallback exists)
src/ui/       React components (App, ParamForm, OptionsMenu, Results, Plot, Logo, csv)
src/styles.css   full CSS-variable theming (`html[data-theme='dark']` override block)
```

Non-negotiables:

- `src/engine/` stays pure TypeScript: no DOM, no React, no window. The worker
  and the UI both import it.
- `src/engine/params.ts` is the single source of truth for parameters: a new
  parameter needs `key`, `label`, `group`, `kind`, `default`, `min/max/step`,
  `help` (every parameter has a "?" tooltip — keep that at 100%), and
  `mcable: true` where Monte-Carlo enrollment makes sense.
- Saved-state compatibility: `state-io.ts` merges saved values onto
  `defaultState()`, so **new parameters must work with old saved states**. Never
  read a saved value without a default fallback. Never rename a key without a
  migration.
- `engine.mortgage.totalInterest` (and `ScenarioResult.totalInterest`) is the
  **horizon total**, not the fixed-period total. Check which one you mean.

## Development strategy

1. **Read before acting.** Read the target file end to end, its tests, its
   call sites, and any `AGENTS.md` on the path. Confirm the language and
   framework from the file, never from the request's phrasing.
2. **Small, reversible steps.** One concern per commit. If a change grows
   beyond one concern, split it before continuing.
3. **Tests accompany behavior.** Engine changes extend the vitest files in
   `src/engine/__tests__/`; UI changes extend `src/ui/__tests__/app-smoke.test.tsx`
   (jsdom). Do not weaken an assertion to make a test pass — find out what
   actually changed.
4. **Prove it with the full gate.** Nothing is "done" when it compiles. Run
   tsc, the full vitest suite, and a production build before every commit.
5. **UI invariants** (these have broken the app before — see `src/ui/AGENTS.md`
   for details):
   - React hooks must come **above** any early `return null` in `Results.tsx`.
   - Tooltips must not be clipped: never reintroduce `overflow: hidden`
     on `.param-box`.
   - Theme changes must recolor Plotly *before* the state update renders
     (`applyTheme()` in the click handler, then `setTheme`).
6. **Ask the simulation, not yourself.** For domain questions (what a German
   payment profile does, tax treatment), extend a test that shows the behavior
   before deciding the implementation.

## Git workflow

- Commits: imperative summary line, blank line, short body only when the
  "why" is not obvious, footer:
  `Generated by Mistral Vibe.` / `Co-Authored-By: Mistral Vibe <vibe@mistral.ai>`
- History rewrites (squash, filter-branch, amend of pushed commits) **only on
  explicit user request**; after any rewrite the user pushes with
  `git push --force-with-lease` from a machine that has their SSH key — this
  sandbox has no GitHub key, so pushes happen from the user's side.
- `plan/` is gitignored on purpose (it was removed from history once). Do not
  re-add it, and never commit personal paths, names, tokens, or e-mail
  addresses — the repo has been audited to be clean and must stay that way.
- CI runs tests + deploy on **Node 24**; jsdom→undici needs >= 22.19. Do not
  downgrade the pin casually.
